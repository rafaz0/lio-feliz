## 1. Objetivo Geral

Esta Product Interpretation (PI-016) documenta retrospectivamente a arquitetura implementada durante a fase de **Experience Layer & Architecture Preservation**, consolidando a criação de uma biblioteca reutilizável de componentes de experiência e a preservação do conhecimento arquitetural para evoluções futuras.

A PI-016 materializa a transição de uma plataforma com módulos funcionais (PI-015) para uma plataforma com experiência de usuário enriquecida, dados reais integrados e arquitetura documentada para os próximos ciclos de evolução.

Nenhuma Frozen Baseline foi alterada. Todas as implementações permaneceram na Presentation Layer.

---

## 2. Motivação

### 2.1 Estado Anterior (Pós PI-015)

A PI-015 estabeleceu os fluxos de navegação, deep linking entre módulos e o Dashboard como Hub Central. No entanto:

- Não existia uma biblioteca reutilizável de componentes de experiência (UX).
- O Dashboard usava componentes inline em vez de componentes modulares.
- Dados mock eram exibidos em seções do Dashboard (RecentActivity, ContextPanel, SmartHints).
- Componentes de navegação (QuickActions, RelatedLinks) eram implementados manualmente em cada página.
- A arquitetura da Gestão Financeira (domínio superior) não estava documentada.
- Os estados operacionais da aplicação não estavam formalmente definidos.

### 2.2 Oportunidades Identificadas

| Oportunidade | Impacto |
|-------------|---------|
| Ausência de biblioteca de UX reutilizável | Duplicação de código entre módulos |
| Dados mock no Dashboard | Usuário vê informações fictícias |
| Gestão Financeira sem documentação | Risco de acoplamento futuro |
| Estados da aplicação não documentados | Dificuldade de planejamento |
| Sem critérios formais de conclusão de EWO | Inconsistência na engenharia |

## 4. Diretrizes Arquiteturais

### 4.1 Princípios da Experience Layer (R-EXP)

A Experience Layer segue 3 regras arquiteturais:

| Regra | Descrição |
|-------|-----------|
| **R-EXP-001** — Composição antes de duplicação | Verificar `src/components/experience/` antes de criar novos padrões de UX inline. |
| **R-EXP-002** — Dados estáticos como preparação | Componentes aceitam props simples. Dados dinâmicos são preparados no módulo consumidor. |
| **R-EXP-003** — Compatibilidade com ModuleLayout | Todos os componentes são compatíveis com ModuleLayout, ModuleSection e Card. |

### 4.2 Separação entre Experience Layer e Presentation Layer

| Camada | Responsabilidade | Localização |
|--------|-----------------|-------------|
| **Experience Layer** | Componentes reutilizáveis de UX, sem fetching próprio | `src/components/experience/` |
| **Presentation Layer** | Páginas, layouts de módulo, orchestration de dados | `src/routes/`, `src/presentation/features/` |
| **Domain Layer** | Regras de negócio, entidades, invariantes | `src/core/domain/` |

A Experience Layer **não faz fetching de dados**. Ela recebe dados prontos via props e renderiza. O fetching é responsabilidade da Presentation Layer (páginas e features).

### 4.3 Separação Carteira vs. Gestão Financeira (ADR-009)

A Carteira de Investimentos e a Gestão Financeira são **domínios independentes**:

| Aspecto | Carteira | Gestão Financeira |
|---------|----------|-------------------|
| Domínio | Investimentos | Finanças pessoais |
| Dependência | Nenhuma | Opcional (opt-in) |
| Integração | — | Flag `FinanceIntegrationConfig` |
| Estado | ✅ Existente | 🔮 Previsto (PI-017/018/019) |

A regra R-PF-001 estabelece: a Carteira deve continuar funcionando integralmente sem a Gestão Financeira.

### 4.4 Dashboard — Estados de Funcionamento

O Dashboard (`/dashboard`) opera em 4 estados:

| Estado | Descrição | Comportamento |
|--------|-----------|---------------|
| **A** | Carteira ativa | Dashboard completo (KPIs, gráficos, insights) |
| **B** | Sem carteira | DashboardEmpty com ações sugeridas |
| **C** | Carteira vazia | Indicadores zerados, fallback |
| **D** | Modo dev sem carteira | Mesmo do Estado B |

A regra R-DB-001 determina: nenhum erro interno deve ser exibido ao usuário. `NotFoundError("Portfolio")` → `DashboardEmpty`.

## 5. Experience Layer — Componentes

### 5.1 Componentes Criados

| Componente | Arquivo | Descrição | Props principais |
|-----------|---------|-----------|------------------|
| `ContextPanel` | `context-panel.tsx` | Painel lateral com seções de informação contextual | `sections: ContextPanelSection[]` |
| `QuickActions` | `quick-actions.tsx` | Grade de atalhos clicáveis para navegação | `items: QuickActionItem[]`, `columns` |
| `RelatedLinks` | `related-links.tsx` | Lista de links relacionados com descrição | `items: RelatedLinkItem[]` |
| `RecentActivity` | `recent-activity.tsx` | Timeline de atividades recentes | `items: RecentActivityItem[]`, `maxItems` |
| `SmartHints` | `smart-hints.tsx` | Dicas contextuais dispensáveis (3 variantes) | `hints: SmartHint[]`, `dismissible` |

### 5.2 Padrão de Implementação

Cada componente:
- Exporta seu tipo de props para reutilização com type safety.
- Aceita `className` via `cn()` para customização.
- Renderiza `null` quando vazio (empty state nativo).
- Usa componentes shadcn/ui (`Card`, `CardHeader`, `CardTitle`, `CardContent`).
- Usa `Link` do TanStack Router para navegação SPA.
- Usa `lucide-react` para ícones.

### 5.3 DashboardEmpty

| Aspecto | Detalhe |
|---------|---------|
| Arquivo | `src/presentation/features/dashboard/components/DashboardEmpty.tsx` |
| Função | Empty state para novos usuários sem carteira |
| Conteúdo | "Bem-vindo ao Dashboard" + ações "Criar carteira" e "Explorar mercado" |
| Acionamento | `NotFoundError("Portfolio")` no DashboardView |
